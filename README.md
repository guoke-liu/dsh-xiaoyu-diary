# 小鱼日记（@local/xiaoyu-diary）

[![tests](https://github.com/guoke-liu/dsh-xiaoyu-diary/actions/workflows/tests.yml/badge.svg)](https://github.com/guoke-liu/dsh-xiaoyu-diary/actions/workflows/tests.yml)
[![license: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

> 记住「不能忘的事」，并且能找回来。每天自动提取候选，由你在 UI 上挑哪些放进日记。

仓库：<https://github.com/guoke-liu/dsh-xiaoyu-diary>

```bash
git clone https://github.com/guoke-liu/dsh-xiaoyu-diary.git
cd dsh-xiaoyu-diary && ./install.sh --dry
```

## 这是什么

小鱼日记是一个 DSH 插件，解决「聊天里那些重要事情转头就忘」的问题。

它分两条路：

- **手动记**：你说「记一下」，模型调 `xiaoyu_diary_write` 写进当天日记。
- **自动提取 + 人来挑**：每天从记忆仓库当天的聊天里按规则筛出候选（承诺、决定、重要信息、情绪、未解决的问题），由你在 UI 上逐条决定「放进去 / 不放」，放进去了就立刻写进当天日记。

日记一天一个 JSON 文件，另有一个反向索引支持关键词与标签检索。UI 有两种模式：挑选模式（勾选候选）和书本模式（一天一页翻着看，记住读到第几页）。

## 特性

- **零第三方依赖**：纯 Node 内置模块 + 宿主注入的 React，不用装任何 npm 包
- **一天一个文件**：追加只重写当天那个文件，写坏了也只坏一天，人能直接打开看
- **索引是派生物**：`entries/` 是唯一真相，索引丢了/坏了/版本旧了都能完整重建
- **候选保留取舍**：重新提取不会冲掉已做的「放进去 / 不放」决定，同一条候选不会第二天又冒出来让你重挑
- **关键词 + 标签检索**：2 字滑窗切词，搜「猫」能命中「橘猫」；标签命中权重更高
- **记忆仓库适配器三档降级**：优先走仓库自己的接口，拿不到再降级读文件，仓库接口断了日记候选也不会断
- **UI 两种模式**：挑选模式逐条勾选候选，书本模式一天一页翻着看、记住读到第几页
- **私聊与群聊完全分开**：每个来源各有独立的日记、候选、书签、索引。绝不混在一起 —— 群友说的话不会混进你的私聊日记

## 安装

插件包根目录是 `plugin/`（含 `package.json` 的那一层），不是外层目录。

### 安装

**推荐直接跑安装脚本**，它会自动找 profile、加依赖、装好并验收：

```bash
./install.sh              # 只有一个 profile 时自动选
./install.sh <profile名>  # 有多个时指定一个
./install.sh --dry        # 只想看看会做什么
```

脚本做的事就是下面这段手工步骤，不想用脚本可以照着做：

```jsonc
// ~/.dsh/profiles/<profile>/package.json
{
  "dependencies": {
    "@local/xiaoyu-diary": "link:/path/to/xiaoyu-diary"
  },
  "dsh": {
    "profile": {
      "bundles": ["@local/xiaoyu-diary"]
    }
  }
}
```

`link:` 必须指向**含 `package.json` 的那一层**（也就是本目录），不能指外层包装目录。

然后安装依赖：

```bash
cd ~/.dsh/profiles/<profile>
dsh plugin --profile <profile> install
```

⚠️ **不要手工往 `cordis.patch.yml` 加本插件条目** —— 本包自带
`dsh.bundle.patch`，安装时会自动应用，手加会导致**重复注册**。

### 远程 / 服务器部署

把本仓库放到服务器上任意位置，profile 的 `package.json` 用**绝对路径** link 过去
（指向包含 `package.json` 的那一层，也就是本目录）：

```jsonc
{
  "dependencies": {
    "@local/xiaoyu-diary": "link:/path/to/xiaoyu-diary"
  }
}
```

改完插件代码后要重启 DSH 服务才生效：

```bash
sudo systemctl restart <你的 dsh 服务名>
```

## 使用

### 先说最重要的一条：日记按来源完全分开

**私聊一本，每个群各一本。** 它们各有自己的日记、候选、阅读进度，互不可见。

为什么这样做：私聊里是你和特定的人的约定；群聊里可能根本不是你在说话。
混在一份日记里，翻的时候分不清哪句是谁说的，检索「上次谁说过要给我带东西」
会搜出群友的闲聊。

来源用一个字符串表示：

| 来源 key | 是什么 | 存成哪个目录 |
|---|---|---|
| `private` | 私聊 | `private` |
| `group:730783833` | QQ 群 730783833 | `group-730783833` |

### 6 个工具

⚠️ **`来源` 参数**：`search` / `read` / `extract` / `llm_pick` 必须传，
不传会返回一行「缺少来源参数，可选：私聊、群 …」而不是猜一个。
`write` 不传默认记到私聊；`list` 不传列全部来源的汇总。

| 工具 | 用途 |
|---|---|
| `xiaoyu_diary_write` | 记一条。**只在用户明确叫你记的时候用**（「记一下」「记下来」「别忘了」），不要自作主张把普通闲聊记成日记。来源不填 = 私聊 |
| `xiaoyu_diary_search` | 按关键词/标签检索**某一个来源**，找回「以前记过的事」。适合用户问「我之前说过什么」 |
| `xiaoyu_diary_read` | 读某来源某一天日记的全部内容。适合「我昨天记了啥」这种回顾 |
| `xiaoyu_diary_list` | 列出有哪些来源、每个来源哪些天有记录、每天几条。也是「不知道该看哪本」的入口 |
| `xiaoyu_diary_extract` | 从记忆仓库**某一个来源**当天的聊天里按**规则**初筛候选。只筛不写、不花钱 |
| `xiaoyu_diary_llm_pick` | 把**某一个来源**当天的聊天交给大模型挑。**花钱、慢**，只在用户明确要求时用。只返回候选，不写日记 |

### 两条挑选通道怎么选

| | 规则筛选（`extract`） | 大模型挑选（`llm_pick`） |
|---|---|---|
| 花钱 | 不花 | 花（或用免费模型） |
| 速度 | 毫秒级 | 十几秒到几分钟 |
| 质量 | 只能抓关键词，会把「开心」当情绪事件 | 能读懂上下文，挑得出「一句真心话」 |
| 适合 | 每天日常、量大 | 一周回顾、想认真挑一次 |

大模型通道需要用户先配好自己的模型（见下节），**开源项目不绑定任何一家服务商**。

### UI 两种模式

设置页 →「小鱼日记」区块。**顶部第一行是「看哪本」下拉框**（私聊 / 各个群），
下面所有内容 —— 候选、日记、书、检索 —— 都只作用于选中的那一本。

| 模式 | 干什么 |
|---|---|
| **挑选**（默认） | 按天列出候选，逐条「放进去 / 不放」，支持批量全放 / 全排除 |
| **书本**（点「📖 翻开日记」切换） | 做成一本可以翻页的书，一天一页，记住翻到第几页（书签） |

书本模式细节：

- 顶部显示 `第 N 页 / 共 M 页` 和当前日期，左右是「上一页 / 下一页」，到头会禁用
- **每个来源各有自己的书签**：在私聊里读到第 3 页，切到群里不会跳到第 3 页
- **跳转**：下拉框列出该来源所有有日记的日期；另有日期输入框，选到没日记的日子只提示「那天没有日记」，不会乱跳
- 一页都没有时显示「还没有任何日记」，不会白屏

切换来源时正在跑的挑选任务会被干净地停掉（不会串到另一本去），
候选和检索结果也会一起清空重拉，不会在上一个来源的数据上操作。

## 数据存在哪

默认目录 `~/.dsh/xiaoyu-diary/`（可用环境变量 `DIARY_HOME` 或 profile 配置 `rootDir` 改位置）：

```text
~/.dsh/xiaoyu-diary/
├── sources.json                          # 有哪些来源出现过（派生物，可重建）
├── entries/
│   ├── private/                          # 私聊的日记
│   │   ├── 2026-11-01.json
│   │   └── 2026-11-02.json
│   └── group-730783833/                  # 群 730783833 的日记
│       └── 2026-11-02.json
├── candidates/
│   ├── private/2026-11-02.json           # 候选 + 取舍状态（pending/accepted/rejected）
│   └── group-730783833/2026-11-02.json
├── index/
│   ├── private.json                      # 反向索引：词 → 天数（派生物，可重建）
│   └── group-730783833.json              # 每个来源一份，各管各的
├── bookmark/
│   ├── private.json                      # 书本模式阅读进度（每个来源各一本）
│   └── group-730783833.json
└── legacy/                               # 老版本数据的备份（只在迁移过的时候存在）
    └── entries-2026-11-03T01-16-35-938Z/
```

- **一天一个文件、一个来源一棵目录**：追加只重写当天那个文件，写坏了也只坏一天一个来源
- **索引是派生物**：`entries/` 才是唯一真相，索引丢了/坏了/版本不对都能完整重建
- **每个来源的 id 各自自增**：私聊里第一条是 `d1`，群里第一条也是 `d1`。所以引用条目一定要带上来源
- **候选保留取舍**：重新提取时已标成「放进去/不放」的候选沿用原状态，不会让你每天重挑一遍

记忆仓库（只读）默认在 `~/.dsh/memory-vault/`（可用 `VAULT_HOME` 或 `vaultDir` 改位置）。

### 从老版本升级

0.2.x 早期是**一天一个文件**（`entries/<日期>.json`），私聊和群聊的条目都塞在这一个文件里 ——
**靠每条自己的 `tags` 第一个元素区分**：

```jsonc
{ "id": "d7", "text": "冥月请风拿人情世故考我…", "tags": ["群聊", "冥月请风", "人情世故"] }
//                                                   ↑ 来源在这里，不在文件名里
```

所以这些数据**可以无损拆开**。插件启动时会自动按标签拆：

- **拆得对**：`tags` 里恰好有 `私聊` → 归私聊那本；恰好有 `群聊` → 归群那本
- **认不出的**（没有来源标签、或两个都有）→ 归私聊，并记进日志的「猜过来源」清单，备份里可复核
- **不删原件**：先复制到 `legacy/entries-<时间戳>/`，原样字节，随时能复核
- **不覆盖新数据**：目标来源已经有同一天的内容，这一天跳过
- **幂等**：搬完就没老文件了，重复启动什么都不做

#### 群聊条目归到哪个群（要人来定）

老条目只有 `群聊` 这个标签，**没有记是哪个群**。程序没法可靠推断 ——
试过用成员昵称匹配，实测 **34 条里只能判对 1 条**，因为很多人早退群改名了
（灰狐、ds深潜、游龙潜吟、路西法… 现在都查无此人）。

所以这一步**要人来定**。自带的命令行工具有两条路子：

```bash
cd <插件根目录>

# 路子一：按群昵称自动分（能判的自动归，判不了的留着）
node tools/归属群聊.mjs bynick --dry     # 先看
node tools/归属群聊.mjs bynick           # 执行

# 路子二：人工指定（一条命令全归到一个群）
node tools/归属群聊.mjs list             # 看有哪些在等归属
node tools/归属群聊.mjs assign group:<群号> --dry
node tools/归属群聊.mjs assign group:<群号>
```

`bynick` 的做法：拿老条目 `tags` 里的人名，去每个群**当前**的成员名单里查。
结果分三档，**只有「能定」的才会被自动归位**：

| 判定 | 含义 | 怎么处理 |
|---|---|---|
| 能定 | 只有一个群命中 | ✅ 自动归到这个群 |
| 判不了 | 两个以上群都有命中 | ⚠️ 留着，报给你 |
| 无依据 | 人名在所有群都查不到 | ⚠️ 留着，报给你 |

⚠️ **实测效果很有限**：真实数据 34 条里只判对了 **1 条**。原因是老日记里的人是
**当时**的，很多人后来退群改名了（灰狐、ds深潜、游龙潜吟、路西法、梁圣、放假dog、廾匸 都查无此人）。
所以 `bynick` 通常只能自动归个位数，剩下的还是要用 `assign` 指定。

工具做的事：

- **真的备份**：整份复制到 `<日记库>.bak-<时间戳>`，不是打印一句就算
- **两处都查**：`entries/` 根下的老文件 + 已经误迁进 `entries/private/` 的
- **幂等**：同一条不会加两次，重复跑安全
- **只动 `群聊` 标签**：私聊条目一条都不碰

| 记忆仓库里有几个群 | 不指定会怎样 |
|---|---|
| 恰好一个 | ✅ 启动时自动归给它 |
| 两个以上 | 群聊条目暂不搬、老文件也不删，等上面那条命令 |

## 工作原理

### 怎么写日记（两条通道）

**规则通道**（`extract` / UI 的「重新提取这天」）：零成本、毫秒级，关键词命中。适合每天日常。

**大模型通道**（`llm_pick` / UI 的「🤖 让大模型挑这一天」）：把**当天全部聊天**分批交给模型，
由模型判断哪些值得记。质量明显更高（能挑出「一句真心话」这种事，规则永远抓不到），但花钱且慢。

#### 配置自己的模型

插件**不绑定任何服务商**。在设置页 →「小鱼日记」→「🤖 大模型通道」里填三样：

| 字段 | 说明 |
|---|---|
| `baseURL` | OpenAI 兼容接口地址，如 `https://open.bigmodel.cn/api/paas/v4`、`https://api.openai.com/v1` |
| `apiKey` | 你的密钥（存在 `~/.dsh/xiaoyu-diary/llm.json`，权限 600，接口只返回 `***`） |
| `model` | 模型名，如 `gpt-4o-mini`、`glm-4-flash` |
| 额外参数 | 选填 JSON，原样合并进请求体，用来透传厂商特有参数 |

**用「思考模型」时注意**：这类模型把思考过程也算进 `max_tokens`，
实测智谱 `glm-5.3-flash` 在 3000 时会思考到没正文。要这样配：

```json
{ "thinking": { "type": "enabled" }, "max_tokens": 6000 }
```

如果遇到「模型返回内容为空」的报错，错误信息会直接告诉你要调大 `max_tokens`。

#### 提示词写长了会翻车（实测）

早先的提示词为了压掉废话，堆到 1131 字，塞满反例和自检，还写了句
「返回空数组是正常且合格的结果」。用免费小模型（Agnes 3.0 flash）实测：

| 提示词 | 100 行真实聊天 | 输出 |
|---|---|---|
| 1131 字（含退出口） | 0 条 | 6 token |
| 491 字（去掉退出口） | 3 条 | 229 token |

根因不是模型能力差，是**那句退出口**：模型宁可交白卷（永远不会错），也不愿承担挑错的风险。
现在控制在 500 字上下、只正面描述"什么值得记"，并由 `test/llm.test.mjs` 守住
「不许出现退出口」「长度不超过 700 字」两条红线。

#### 限流与重试

免费通道的 RPM 很低，实测同一天 4 批**全部 429**——串行并不能避免限流。
所以加了退避重试：只对 429 / 超时 / 5xx 重试（2s、4s），
鉴权错误和非法 JSON 不重试（重试也是白等）。

#### 分批与去重

- **分批**：默认每批 400 行、串行调用（不并发，避免撞限流）。实测最大的一天 2363 行 → 6 批。
  某一批失败不中断，其余批次结果照常返回。
- **去重**：**把当天已记的内容作为上下文交给模型，让它自己避开**。
  不能靠事后文本相似度——模型每次措辞都不同，实测两句话的 2-gram Jaccard 相似度只有 0.22，
  任何阈值都会漏判。模型侧避开之后再兜一层「规范化 + 双向包含」的字符串比对捡漏。

#### 进度显示（为什么是异步任务）

一天 6 批、思考模型每批 40-60 秒，总共好几分钟。**同步请求会让用户以为卡死**，
所以 UI 走异步任务：

```
POST /llm-pick-async   → 立刻返回 jobId（不阻塞）
GET  /llm-pick-progress?jobId= → 每 2 秒问一次，拿 {状态, 已完成, 总批数}
POST /llm-pick-cancel  → 取消
```

关键设计：

- **同一天只跑一个任务**：狂点按钮复用同一个 jobId，不会一次烧 N 倍的钱。
- **前端用 `setTimeout` 递归而非 `setInterval`**：请求回来后才排下一次，保证同一时刻只有一个在途请求，
  慢网下不会堆积。
- **任务表会自己清理**：完成超过 10 分钟的任务删除、最多保留 20 条；
  淘汰时跳过 running 任务（删了它后台还在烧钱，却再也够不着进度和取消）。
- **同步接口仍然保留**（`POST /llm-pick`）：工具调用和自动化场景不需要进度。

### 候选提取为什么只做初筛

`lib/extract.js` **不做语义理解**——它判断不了「这句话对他重不重要」。它只用五类可解释的规则筛出「可能值得记」的候选，交给模型或人在 UI 上做最终取舍。

| 类别 | 权重 | 线索词举例 |
|---|---|---|
| 承诺/计划 | 3 | 明天、下周、约好、答应、我记得、别忘了 |
| 决定/结论 | 3 | 决定、就定、定了、以后就、规定、原则 |
| 重要信息 | 4 | 密码、地址、电话、多少钱、截止、合同 |
| 情绪强度 | 2 | 气死、崩溃、委屈、失望、舍不得 |
| 未解决 | 2 | 怎么办、没搞定、报错、卡住、崩了 |

筛完通常剩几条，人扫一眼就能挑。规则可读，筛错了能查出是哪条词的问题。

**词表靠人工维护，加词前先想清楚误报率。** 三条硬规则来自真实数据实测（云端 367 行聊天）：

1. **泛动词不收**：「安排」「改成」「换成」在画图/闲聊里满天飞，曾让 222 行筛出 23 条几乎全是垃圾。
2. **没有信号就不算候选**：长度加分只是修正项，**必须先命中至少一类信号**才生效。曾因长度分独立生效，让「搬家公告」「URL」这类长废话混进候选。
3. **日常寒暄不算情绪**：「开心」「高兴」是高频寒暄词，一天能占满 4 个名额。只收「发生了某件事」级别的强度词（崩溃、委屈、舍不得）。

收紧后 367 行 → 7 条候选（命中率 1.9%），每条都确实像「值得记的事」。这三条都在 `test/diary.test.mjs` 里有回归测试盯着。

### 怎么接入记忆仓库（重点：适配器三档降级）

`lib/vault.js` 实现了三档降级策略，保证仓库接口断了日记候选也不会断：

| 档位 | 做法 | 什么时候用 |
|---|---|---|
| **档 A** 包名解析 | `require.resolve('dsh-memory-vault/package.json')` 从若干基准目录找包，动态 import 它的 `lib/tools.js` 和 `lib/chatlog.js` | 最正确：不关心仓库装在哪、怎么装的 |
| **档 B** 直接路径 | 已知仓库在本机的固定物理路径，直接 import | 档 A 落空时（仓库手工放的、不进 npm 解析链） |
| **档 C** 降级读文件 | 直接扫 `chat/` 目录 + 复用 `extract.js` 的行解析 | 接口根本拿不到时的保底防线 |

关键取舍：**档 C 不是首选，是保底。** 一旦拿到接口就优先走接口；只有拿不到接口，才退到直接读文件。

### 检索怎么做

零依赖，不花 LLM 钱。中文按 2 字滑窗切词（与记忆仓库做法同源但独立实现）：

- 搜「猫」能命中「橘猫」，搜「服务」能命中「服务器」
- 标题命中 ×2，标签精确命中 +3（标签是人手工打的，比正文里偶然出现的词可信）
- 同一个词重复出现只算一次分（否则一段话里啰嗦地重复几次就能把无关的日记顶上来）

## 已知限制

### 来源相关的

- **老数据无法拆回来源**：0.2.x 早期混着存的那几天，整体归到了私聊（见「从老版本升级」）
- **来源从记忆仓库目录推出**：记忆仓库没有「列群号」的接口，只能读 `chat/group/<群号>/` 目录名。
  仓库改了目录布局就得跟着改
- **群没有名字，只有群号**：记忆仓库只存群号目录，不存群名。UI 上显示的是「群 730783833」。
  想显示好认的名字，得另外配一份群号→名字的映射（尚未实现）
- **群被删掉后日记还在**：来源清单只增不减。仓库里删了某个群，那本日记照样能翻，
  只是再也不能重新提取候选了（不是 bug，是有意的 —— 记下的东西不该因为来源消失就不见）
- **同名群号冲突**：来源 key 只有群号，没有平台前缀。同时接两个 QQ/微信实例且群号撞了会合并

- **路由不做鉴权**：HTTP 路由本身没有访问控制，靠宿主登录态 + 网络边界（127.0.0.1 / 内网）保护。要收紧权限就在 `routes.js` 里加。
- **UI 的纯计算已有正式测试，但交互仍需手工回归**：翻页计算、进度百分比这些纯逻辑已抽到 `lib/view.js`，由 `test/view.test.mjs` 覆盖（含一条"副本一致性"测试，防止 `client.js` 里的内联副本与 `view.js` 漂移）。但**事件交互**（点按钮、卸载清理定时器）仍只能靠临时脚本验。改 `client.js` 时请手工回归。
- **词表靠人工维护**：`extract.js` 里的信号词表是拿真实数据调过的，但不是自动的。加词前要先想清楚误报率，泛动词（安排、改成、换成）不能加回去。
- **只调过私聊数据**：信噪比是用 3 天真实私聊（367 行）调的，群聊样本只有 1 天（152 行）。实测群聊信号率 2.6%、私聊 3.7%，**没有证据表明群聊噪音更大**，但也谈不上调优过。
- **进度轮询的调度没有正式测试**：轮询后端 7 条测试在 `test/async.test.mjs`；进度条数值计算在 `test/view.test.mjs`。但「每 2 秒问一次 / 完成后停 / 卸载清定时器」这套调度只有临时脚本验过。
- **记忆仓库接口可能静默失效**：三档降级能兜住，但如果仓库既没装、文件布局也变了，当天就没有候选——表现为「那天没聊什么」，需要看日志里的 `[vault]` 提示确认。
- **任务进度只存在于内存**：dsh 重启后未完成的任务丢失，前端轮询会收到 404。这是刻意的取舍（为一个几分钟的任务做持久化不值得），但用户重启后会看到「任务不存在或已过期」。

## 附一：手机访问（可选）

云端 DSH 默认只监听 `127.0.0.1`，手机上打不开。想在外面用：
反向代理一条路径 + `--trusted-host`。

```nginx
location /dsh/ {
    auth_basic off;              # 靠 DSH 自己的 token 认证
    proxy_pass http://127.0.0.1:6600/;
    proxy_set_header Host $http_host;   # ⚠️ 必须带端口，不能用 $host
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 3600s;
    proxy_buffering off;
}
```

```ini
# 你的 dsh service 单元
ExecStart=/usr/bin/dsh --profile <profile> --host 127.0.0.1 --port <port> --trusted-host <公网IP>:80 --no-open
```

访问地址：`http://<公网IP>/dsh/?token=<dsh 打印的 token>`

**四个必须知道的坑**，简要说：
`$http_host` 不能用 `$host`、`auth_basic off` 要显式写、`ExecStartPost` 时机早于 DSH 就绪、
curl 测链接要带 cookie jar（否则会看到假 401）。
